# Council

A council of AI agents that deliberates on a question: a Red Team, a First
Principles thinker, an Expansionist, an Outsider and an Executor, run by a
moderator, reviewed blind, and summarized by a consensus chair and a dissent chair.

## Setup

```bash
uv sync                       # installs dependencies (and pytest for tests)
```

Put your key in `.env`:

```
OPENAI_API_KEY=sk-...
```

Each agent's model is the `llm:` line in `src/council/config/agents.yaml`.

## Try it

Start with the free and cheap options, in this order:

```bash
uv run pytest                                   # offline tests, no API calls
uv run council "Should we ...?" --dry-run       # whole pipeline, canned outputs, free
uv run triage "Should we ...?"                  # one real call: checks key + model
uv run council "Should we ...?" --mode quick    # cheapest real run
uv run council "Should we ...?"                 # the moderator picks the depth
```

`crewai run` also works; it asks for a question.

**If Windows blocks a command** ("blocked by Smart App Control"): uv runs these
commands through small launcher programs it creates in `.venv\Scripts`
(`council.exe`, `triage.exe`, `pytest.exe`...). They're unsigned and exist only
on your machine, so Smart App Control may refuse them. Run the same commands
through Python instead; nothing else changes:

```powershell
uv run python -m council "Should we ...?" --dry-run
uv run python -m council triage "Should we ...?"
uv run python -m council "Should we ...?" --mode quick
uv run python -m council outcome <run_id> success "notes"
uv run python -m pytest
```

The only inputs are the question, optional background (`--context`) and
documents (`--docs`), and an optional `--mode quick|standard|deep`.
Everything else is generated by the flow. Put the question first.

| Mode     | Advisors | Decision science | Debate |
|----------|----------|------------------|--------|
| quick    | 3        | no               | no     |
| standard | 4        | no               | yes    |
| deep     | 5        | yes              | yes    |

## Giving the council background and documents

```bash
uv run council "Should we bid on the DOT training RFP?" --context notes.md --docs rfp budget.xlsx
```

**`--context`** is your background, in your own words: the situation,
constraints, what you've already ruled out. Pass the text itself
(`--context "Two staff, booked through March"`) or a file (`--context notes.md`).
A file is easier for anything longer than a sentence, and avoids quoting trouble.
Every advisor sees it word for word.

**`--docs`** attaches files and folders to this one question: RFPs, budgets,
plans, emails saved as text. Folders are read recursively.

| Reads | Doesn't read |
|---|---|
| PDF, Word (.docx), Excel (.xlsx), and text formats (.md, .txt, .csv, .json, .html...) | Scanned PDFs (no text layer; run OCR first), old .doc/.xls (re-save as .docx/.xlsx), images, PowerPoint (export to PDF) |

Before any model is called, the command lists what it loaded and what it
skipped and why. A path that doesn't exist stops the run straight away.

How documents are used:

- The moderator reads all of them in full while framing the question (step 3).
- Every advisor gets them verbatim in their brief, up to `COUNCIL_DOC_BUDGET`
  characters in total (default 30,000, about 7,500 tokens). Beyond that, short
  documents stay whole and long ones are excerpted; the moderator's summary
  covers the rest.
- The report lists them as sources; the transcript and journal record which
  files were used.

Documents in the brief are sent to every advisor, so a larger budget costs
more per run. For a quick test, keep attachments small or use `--mode quick`.

**No `--docs`?** Then the moderator looks through the shared `workspace/`
folder (or `COUNCIL_WORKSPACE`) for anything relevant and says which files it
used. Handy for standing material, such as your rate card or service
descriptions, that applies to most questions.

## Running on a local model (Ollama)

Point every agent at a model Ollama has pulled:

```powershell
$env:COUNCIL_MODEL = "ollama/qwen3:14b"      # or put COUNCIL_MODEL=ollama/qwen3:14b in .env
uv run council "Should we ...?" --mode quick
```

Ollama is found at `OLLAMA_HOST` (default `localhost:11434`); CrewAI doesn't
read `OLLAMA_BASE_URL`. Before the run starts, the command checks that Ollama
is answering there and has the model, and tells you the `ollama pull` command
if not.

**Raise Ollama's context window first.** By default Ollama gives a model
4,096 tokens of context on machines with less than 24 GB of VRAM, and when a
prompt is longer it silently drops the beginning, which is where each agent's
instructions are. Council prompts (brief, bias audit, documents) are longer
than that. On Windows: quit Ollama from the taskbar, add a user environment
variable `OLLAMA_CONTEXT_LENGTH` = `16384` (or `32768` if you have the
memory), and start Ollama again. The council can't set this per request.

Local models vary a lot in how well they follow structured-output and
tool-calling instructions, which this pipeline relies on. Start with
`uv run triage "..."` (one call), then `--mode quick`.

## Cost and runaway protection

- **Token limit.** A run stops once it has used `COUNCIL_MAX_TOKENS` tokens
  (default 500,000), or `--max-tokens N` for one run; `0` means no limit. The
  next model call is refused, so stopping costs nothing, and the transcript
  keeps everything done up to that point.
- **Loop limits.** Each agent gets a fixed number of rounds: 3 for agents
  without tools, 6 for the intake moderator, 10 for the debate moderator
  (CrewAI's default is 25 for every agent). A failed task is retried once.
- **Delegation only in the debate.** Only the debate moderator can put
  questions to other agents.
- **Where the tokens went.** The command prints tokens per step as it goes and
  the total at the end; the transcript ends with a table by step and agent, and
  the journal records each run's total.

A normal quick run makes about 14 model calls, a standard run about 17, and a
deep run a few more plus the debate's questions. Far more calls than that in
the transcript's usage table points at a step that's looping.

## What a run produces

- `output/<run_id>/report.html`: the council's report
- `output/<run_id>/transcript.md`: every step's raw output, plus which advisor
  was behind each anonymized "Response A–E"
- `journal/council.jsonl`: one line per run; later runs search it (step 2)

Record how a decision turned out, so future runs can learn from it:

```bash
uv run outcome 20260929-133054-1d50 success "won the pilot"
```

Dry runs write to `output/dry-run/` and `journal/dry-run.jsonl` instead.

## Useful settings (environment variables)

| Variable            | Effect                                                   |
|---------------------|----------------------------------------------------------|
| `COUNCIL_MODEL`     | Use one model for every agent (e.g. a cheap one to test) |
| `DECISION_MODEL`    | Model for step 6 only; pick a different family from the advisors |
| `COUNCIL_WORKSPACE` | Shared folder the moderator checks when no `--docs` are given (default `./workspace`) |
| `COUNCIL_DOC_BUDGET` | Characters of document text included in each advisor's brief (default 30000) |
| `COUNCIL_MAX_TOKENS` | Stop a run past this many tokens (default 500000; 0 = no limit) |
| `OLLAMA_HOST` | Where Ollama runs (default `localhost:11434`) |
| `COUNCIL_VERBOSE=0` | Hide agent-by-agent logging (same as `--quiet`)          |

## How it's built

`src/council/flow.py` runs four crews in order: Triage (step 1), Intake
(steps 2–4), Advisors (steps 5–6) and Review (steps 7–10). A rejected question
stops after triage. See the docstrings in `crew.py` and `flow.py` for why it's
split this way. `uv run plot` draws the flow.
